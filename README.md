# Анкета відбору пілотів БпЛА

Статичний сайт (HTML/CSS/JS) для попереднього відбору кандидатів на підготовку
пілотів БпЛА. Форма доступна за публічним посиланням без реєстрації; відповіді
зберігаються в Supabase. Прихована сторінка з результатами доступна лише після
входу в обліковий запис, який ви самі створите в Supabase Auth.

## Живий сайт

- Анкета: https://kpyk79.github.io/uav-pilot-survey/
- Результати (штаб): https://kpyk79.github.io/uav-pilot-survey/panel-9f2e7c.html
  (вхід — email drozdairdrop@gmail.com, пароль видано окремо в чаті при налаштуванні)
- Supabase-проєкт: uav-pilot-survey (org Kpyk79's Org, регіон eu-west-1)

## Структура

```
index.html            — публічна анкета (6 кроків)
panel-9f2e7c.html      — прихована сторінка результатів (не індексується, посилання нікому не давайте)
css/style.css          — стилі анкети
css/panel.css          — додаткові стилі панелі результатів
js/config.js           — URL і anon key вашого проєкту Supabase (заповнити)
js/main.js             — логіка анкети й відправка в Supabase
js/characteristics.js  — правило-базований скоринг і коротка характеристика кандидата
js/panel.js            — логіка входу й списку кандидатів
supabase/schema.sql    — SQL для створення таблиці й політик доступу
robots.txt             — забороняє пошуковикам індексувати сторінку результатів
```

## Крок 1. Створення проєкту Supabase

1. Перейдіть на https://supabase.com → **Start your project** → увійдіть
   (GitHub/Google) → **New project**.
2. Вкажіть назву (напр. `uav-selection`), пароль бази даних (збережіть його) і регіон.
3. Дочекайтесь створення проєкту (1–2 хв).

## Крок 2. Створення таблиці та політик доступу

1. У бічному меню відкрийте **SQL Editor** → **New query**.
2. Вставте весь вміст файлу [`supabase/schema.sql`](supabase/schema.sql) і натисніть **Run**.
   Це створить таблицю `candidates` і налаштує RLS так, що:
   - будь-хто (анонімно) може лише **додати** анкету;
   - бачити список анкет може лише **автентифікований** користувач.

## Крок 3. Вимкнення самостійної реєстрації та створення облікового запису для штабу

1. **Authentication → Providers → Email** — переконайтесь, що лишається увімкненим email/пароль.
2. **Authentication → Settings** (або **Sign In / Providers**) → вимкніть
   публічну реєстрацію (**"Allow new users to sign up"** → вимкнути), щоб ніхто
   стороння не міг сам створити акаунт і зайти на сторінку результатів.
3. **Authentication → Users → Add user** → створіть один обліковий запис
   (email + пароль) для себе/штабу. Саме цими даними ви будете заходити на
   `panel-9f2e7c.html`.

## Крок 4. Ключі API

1. **Project Settings → API**.
2. Скопіюйте **Project URL** і **anon public** key.
3. Відкрийте [`js/config.js`](js/config.js) і вставте їх:

```js
window.SUPABASE_CONFIG = {
  url: "https://xxxxxxxx.supabase.co",
  anonKey: "eyJhbGciOi...",
};
```

`anon` ключ публічний і призначений саме для клієнтського коду — реальний
захист дають RLS-політики з кроку 2, а не секретність цього ключа.

## Крок 5. Локальна перевірка

Відкрийте `index.html` у браузері (або через будь-який статичний сервер,
напр. `npx serve .`), заповніть і відправте анкету, перевірте, що запис
з'явився в Supabase **Table Editor → candidates**. Потім відкрийте
`panel-9f2e7c.html`, увійдіть обліковим записом з кроку 3 і перевірте список.

## Крок 6. Публікація на GitHub Pages

```bash
git init
git add .
git commit -m "UAV pilot selection survey"
git branch -M main
git remote add origin https://github.com/<ваш-акаунт>/<назва-репозиторію>.git
git push -u origin main
```

Далі на GitHub: **Settings → Pages → Build and deployment → Source: Deploy
from a branch → Branch: main / (root)**. Сайт з'явиться за адресою
`https://<ваш-акаунт>.github.io/<назва-репозиторію>/`.

## Безпека сторінки результатів

- Сторінка `panel-9f2e7c.html` не захищена "по-справжньому" (це статичний
  файл, його адресу видно у вихідному коді й історії запитів), тому:
  - не публікуйте й нікому не пересилайте це посилання;
  - тримайте репозиторій **приватним**, якщо не хочете, щоб ім'я файлу було
    видно у відкритому GitHub-репозиторії (`Settings → General → Danger Zone
    → Change visibility`); для приватних репозиторіїв GitHub Pages потрібен
    платний план GitHub, тому альтернатива — тримати код у приватному
    репозиторії для розробки, а для публікації Pages використати окремий
    публічний репозиторій лише зі скомпільованими файлами, перейменувавши
    `panel-9f2e7c.html` на свій довший і унікальний слаг;
  - головний захист — вхід через Supabase Auth (крок 3): без email+пароля,
    створеного вами, список анкет **не завантажиться** — анонімний ключ має
    право лише додавати записи, а не читати їх (це забезпечує RLS).

## Коротка характеристика кандидата

На сторінці результатів кожна анкета автоматично отримує рейтинг (0–100) і
набір тегів (`js/characteristics.js`): досвід з БпЛА/авіацією, рівень
технічних навичок, стресостійкість, потреба в житлі тощо. Це проста
евристика на основі відповідей, а не медичний чи психологічний висновок —
використовуйте її як орієнтир для подальшого особистого інтерв'ю.
